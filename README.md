# Secure Firmware Update Engine（本地模拟）

一个无外部服务、无真实密钥材料的本地固件安全更新引擎模拟，覆盖：

- **签名与完整性校验**：Ed25519（种子确定性派生的测试钥）+ SHA-256，固定顺序校验，
  失败给出可区分错误码（未知钥/过期/未生效/用途不符/坏签名/载荷被篡改）。
- **版本推进与防回滚**：严格版本递增；降级、同版本重放、型号/目标不符分别拒绝；
  轮换期多钥并存时只按包内 KeyID 做唯一确定性判定，不静默择优。
- **暂存/激活/回滚**：A/B 双槽 + 原子启动指针，写入中断、激活前掉电、试运行失败
  均保证设备停留在已知良好版本；重复操作幂等；显式与自动回滚最终状态一致。
- **连续升级**：确认健康后可直接接着装下一个更高版本（v1→v2→v3→…），无需回滚、
  清空或重新初始化；密钥轮换窗口内每个包仍按包内 KeyID 得到唯一确定结论。
- **有界版本历史**：设备只保留“当前版本 + 上一个可回滚的已知良好版本”，旧版本
  清理融合在下一次暂存中。每次打开设备或开始操作前都会**以磁盘上的真实槽文件
  （元数据 + 载荷 SHA-256）对一次账**：清理中途断电/写坏后，即使不走开机恢复，
  直接查状态或回滚，报告版本也始终等于实际在跑的载荷；坏槽不会再被启用，设备停留
  在可启动的已知良好版本上，随后照常继续升级。
- **并发与重复提交（跨进程）**：所有入口由进程内互斥量 + 设备目录上的 `flock`
  跨进程排他锁串行化，一次完整安装全程持锁。两个**独立 OS 进程**同时升级同一台设备
  时，恰好一个装成功，另一个拿到稳定可复现的 `update_in_progress` 拒绝，绝不双成功、
  绝不覆盖已报成功的更新；同一份更新（版本+载荷哈希相同）并发重复提交与单次提交
  完全一致（两边都 `installed`、只落地一次），并发下不会把状态写到读不出来。CLI 与
  库 API 逐步结论完全一致，并有真正 `exec` 多进程的自动化测试覆盖。

详细设计、密钥轮换/回滚规则与本地验证步骤见 [docs/DESIGN.md](docs/DESIGN.md)。

快速开始：

```bash
go test ./... -v
go run ./cmd/fwupdate init
```
